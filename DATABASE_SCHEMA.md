# Database Schema

The backend uses PostgreSQL via Prisma. The schema is declared in `backend/prisma/schema.prisma`.

## Entities

### User

- `id`: UUID primary key
- `fullName`, `email`, `passwordHash`
- `roles`: relationship to `UserRole`
- `wallets`: user wallet records
- `madeTokenRequests`, `checkedTokenRequests`, `approvals`, `auditLogs`

### Role

- `id`: UUID
- `name`: enum `RoleName` (`ADMIN`, `MAKER`, `CHECKER`, `EXECUTOR`)

### UserRole

- associative table linking users and roles
- unique constraint on `[userId, roleId]`

### Wallet

- `walletAddress`: unique Solana wallet address
- `userId`: owner reference
- `label`, `isPrimary`, `isActive`

### ManagedToken

- token mint metadata stored for on-chain mints
- includes `mintAddress`, `decimals`, authority addresses, `metadataUri`, and `creatorUserId`

### TokenRequest

- core on-chain token action request entity
- `requestType`: enum `MINT`, `TRANSFER`, `BURN`
- `status`: enum lifecycle state
- `makerUserId`, optional `checkerUserId`
- `executionMode`: `SERVER_MANAGED` or `BROWSER_WALLET`
- source and destination wallet metadata for token transfers
- on-chain tracking fields such as `txSignature`, `explorerUrl`, and execution timestamps

### RequestApproval

- stored approval actions for token requests
- `action`: `APPROVED` or `REJECTED`
- `checkerUserId` references the reviewer

### Bank

- external bank integration metadata
- supports BIPS and BTN settlement modes
- includes treasury wallet address and issuer flags

### BankAccount

- bank account records for payment or settlement operation
- unique per bank, account type, and number

### BankTokenAccount

- token account records associated with a bank
- includes `mintAddress`, `tokenAccountAddress`, and `purpose`

### ReserveLedger

- tracks reserved BTN balances for issuers
- includes approved/consumed/locked amounts and status

### SettlementRequest

- request entity for reserve mint, interbank transfer, replenishment, redemption
- includes bank references, reserve ledger references, payment metadata, and BIPS tracking

### PaymentTransaction

- raw payment gateway transaction records
- contains callback payloads and status history

### BipsTransactionLog

- BIPS integration log store for request/response payloads

### AuditLog

- portal audit trail entries keyed by actor user and entity type
- useful for compliance and operational review

## Indexing

Important indexes help query performance for status, creation time, user relations, and account identifiers.

- `User.email` unique index
- `Wallet.walletAddress` unique index
- `ManagedToken.mintAddress` unique index
- `TokenRequest.status`, `createdAt`, `makerUserId`
- `SettlementRequest.status`, `reserveLedgerId`, `sourceBankId`, `destinationBankId`
- `ReserveLedger.status`, `bankId`, `approvedByUserId`
- `AuditLog.entityId`, `entityType`, `actorUserId`

## Relationships

- `User` has many `Wallet`, `TokenRequest`, `RequestApproval`, `AuditLog`, and `ManagedToken`
- `Bank` has many `BankAccount`, `BankTokenAccount`, `ReserveLedger`, and `SettlementRequest`
- `ReserveLedger` belongs to `Bank`
- `SettlementRequest` may reference source and destination banks
- `TokenRequest` may reference source and destination wallets and maker/checker users

## Deployment notes

- Prisma client is generated by `npx prisma generate`
- schema changes should be applied with `prisma migrate dev` or `prisma db push`
- use `DATABASE_URL` or split DB config variables as configured in `backend/src/config/env.js`
